# LJ OS Git Wall

LJ OS Git Wall is a local-first Obsidian plugin that turns daily Git activity
into a clean, customizable Daily Note section.

It pairs with the companion CLI, which scans local repos and writes JSON into
your vault. The plugin reads that JSON and renders it into a Git Wall.

```text
PowerShell CLI -> JSON in vault -> Obsidian plugin -> Daily Note Git Wall
```

## Who This Is For

Git Wall is for developers and Obsidian users who want:

- daily Git activity snapshots
- end-of-day review
- weekly note context
- project journaling
- a quick reminder of which repos changed today
- less "what did I work on?" friction

## Companion CLI Required

This plugin reads JSON generated by:

https://github.com/LJrobinson/obsidian-lj-os-cli

The CLI scans local Git repositories and writes one JSON file per day into your
Obsidian vault. This plugin renders that file into a Daily Note.

The plugin does not call Git directly.

## Example Output Gallery

## Manual Install

Copy these release files into:

```text
<vault>/.obsidian/plugins/lj-os/
```

Required plugin files:

```text
main.js
manifest.json
```

Then:

1. Reload Obsidian plugins.
2. Enable **LJ OS** / **Git Wall** in Community plugins.
3. Generate today's JSON with the companion CLI.
4. Run command: **LJ OS: Insert Today's Git Wall**.

There is no build step, npm install, or `styles.css` file required for the
current release.

## Expected Vault Paths

Default Git Wall data folder:

```text
LJ OS/stats
```

Default JSON path:

```text
LJ OS/stats/YYYY-MM-DD.json
```

Default Daily Note folder:

```text
Daily Notes
```

The Daily Note folder is configurable in plugin settings.

## Command

| Command | Purpose |
| --- | --- |
| **LJ OS: Insert Today's Git Wall** | Insert or replace today's Git Wall section. |

There is no command for opening raw JSON. The JSON is internal data between the
CLI and plugin.

## Settings

| Setting | Default | What it controls |
| --- | --- | --- |
| Git Wall data folder | `LJ OS/stats` | Where the plugin reads CLI JSON. |
| Daily note folder | `Daily Notes` | Where dated notes are created or updated. |
| Use emoji | On | Emoji-forward or plain rendered output. |
| Show summary section | On | Shows or hides summary output. |
| Summary style | `callout` | `callout`, `scoreboard`, or `pit-wall`. |
| Show repository section | On | Shows or hides repo output. |
| Repo view | `table` | `table` or `status-cards`. |
| Table format | `standard` | `compact`, `standard`, `detailed`, or `emoji-board`. |
| Show tidy-up section | On | Shows or hides tidy-up output. |
| Tidy view | `queue` | `queue` or `shutdown-checklist`. |
| Show customized label settings | Off | Shows title and section-name fields. |
| Daily section heading | `## 🧱 Git Wall` | Replacement marker for the Git Wall block. |
| Summary title | `🏁 Git Wall` | Summary callout title. |
| Repository section title | `🧰 Repo Garage` | Repo section heading. |
| Tidy-up section title | `🧹 Tidy-Up Queue` | Queue section heading. |

Changing the Daily section heading changes the replacement marker. If you
change it after inserting a Git Wall, delete or rename the old heading in your
Daily Note once.

The **Customize Labels** section includes a **Reset labels** button that
restores the default Git Wall headings and titles.

## Render Views

Summary styles:

- **Callout**: Obsidian summary callout.
- **Scoreboard**: stat table with one metric per row.
- **Pit Wall**: interpreted status table for activity, cleanup, push, and sync.

Repo views:

- **Table**: uses the selected table format.
- **Status Cards**: one Obsidian callout per repo, using success/warning state.

Table formats:

- **Compact**: repo, branch, status, commits.
- **Standard**: repo, branch, commits, status, unpushed, behind, latest.
- **Detailed**: standard plus repo path.
- **Emoji Board**: compact visual board for activity, tidy, push, and pull.

Tidy views:

- **Queue**: simple list of repos needing tidy-up.
- **Shutdown Checklist**: checkbox list for tidy-up, push review, and sync review.

All views render the same CLI JSON. They do not change the JSON schema or make
the plugin scan repositories.

## Emoji Mode

Emoji mode changes rendered output, but it does not rewrite saved setting text.

For example, your Summary title setting can stay `🏁 Git Wall`. When emoji mode
is off, the plugin renders it as `Git Wall` without editing the saved setting.

## Troubleshooting

**Nothing inserted into my Daily Note**

Check that today's JSON exists at `LJ OS/stats/YYYY-MM-DD.json` inside your
vault.

**The plugin says today's Git Wall data is missing**

Run the companion CLI first, then run **LJ OS: Insert Today's Git Wall** again.

**My old heading still appears**

The Daily section heading setting is used to find and replace the block. If you
change the heading, delete the old Git Wall section once.

**Emoji toggle looks like it did not change settings**

Expected. Emoji mode affects rendering only; it does not rewrite saved title
fields.

**Wrong Daily Note folder**

Update the **Daily note folder** setting.

**The plugin does not scan Git repos**

Correct. The CLI scans repos. The plugin only renders JSON.

**Can I open the raw JSON?**

Not through this plugin. JSON is internal data. Use your editor or file explorer
if you are debugging.

## Privacy / Local-First

Git Wall stays local:

- no cloud service
- no GitHub API required
- no telemetry
- no Git calls from the plugin
- no external app opening from the plugin
- plugin reads JSON from your vault
- Git scanning happens outside the plugin in the companion CLI
